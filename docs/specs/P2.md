## 0. 목표와 완료 그림

`npm run seed && npm run build && npm start` 후 `http://localhost:7777/charts` 를 열면:
1. 차트셋 선택 → **자체 생성 시드** `HU push/fold 10bb` (7절) 가 뜬다. 포지션 탭 `SB | BB`, 브레드크럼 루트.
2. SB 탭: 169 격자가 **액션별 색 누적** (예: `A`=빨강, `F`=회색) 으로 그려진다. 셀 호버 → `AKs · A 100% · EV +1.42bb`. 셀 클릭 → 우측 패널에 콤보 4/6/12 개의 액션별 빈도·EV.
3. 브레드크럼에서 `A` 클릭 → BB 노드 (`seq = "A"`): BB 탭이 활성화되고 `C`/`F` 격자. **BB 의 도달 레인지는 100%** 이고, SB 탭의 `seq=""` 노드에서 `F` 를 고른 콤보는 `A` 노드에서 SB 도달 레인지에서 빠진다 (`GET /api/charts/:id/range`).
4. `ggto-json` 파일 하나를 `tools/chart-import` 로 넣으면 같은 화면에 새 차트셋이 뜬다. 잘못된 파일(합이 1이 아닌 전략, 불법 액션, 포지션 불일치)은 **행 번호와 이유**를 찍고 exit 1, DB 는 변경되지 않는다 (트랜잭션).

**시작 조건 (P2 게이트, Phase -1 쟁점 3-2 의 수정본)**: 외부 시드 차트 확보를 **기다리지 않는다**. 7.1 의 자체 생성 차트가 파이프라인 검증의 1순위 시드이고 P2 DoD 는 그것으로 닫힌다. 외부 차트(7.2)는 확보되면 같은 임포터로 들어온다.

**만들지 않는 것**: 트레이너(P3), 솔버(P4), 포스트플랍 UI(P5), 레인지 편집기, 6-max 멀티웨이 시드 생성(7.1 은 HU 뿐), PioSOLVER/GTO+ 파일 어댑터 (샘플 파일이 없는 포맷의 어댑터는 쓰지 않는다 — 6.3), 인증.

## 3. 도메인 정의 (전부 고정)

### 3.1 액션 시퀀스와 노드
- 노드 키 = P0 4.7 정규 문자열. **루트는 빈 문자열 `""`**. 프리플랍만이므로 `/` 없음.
- 노드의 `hero_pos`, `pot_bb`, 합법 액션은 저장 시 `preflopState(config, parseActionSequence(seq)[0] ?? [])` 로 **검증**한다. 파일이 주는 값과 상태 기계가 다르면 임포트 실패. 단일 진실 = 상태 기계.
- 노드의 `actions` 는 파일이 준 토큰 목록 (합법 액션의 **부분집합**이어야 함, 순서 보존, 중복 금지). 차트가 모든 합법 액션을 다 갖지 않는 것은 정상 (예: 특정 레이즈 사이즈만).

### 3.2 전략 블롭
- `strategy[a][c]`, `a ∈ 0..n_actions-1`, `c ∈ 0..1325` (P0 콤보 인덱스), **f32 LE, row-major, zstd**. 압축 전 길이 `4 × n_actions × 1326`.
- 불변식: 각 콤보 `c` 에 대해 `Σ_a strategy[a][c] ∈ [1−1e-4, 1+1e-4]` 이고 각 값 `∈ [0,1]`. 프리플랍은 보드가 없으므로 1326 전부 정의된다. **합이 0 인 열은 허용하지 않는다** (도달 불가는 도달 레인지가 표현한다, 전략이 아니다).
- 169 해상도 파일은 임포터가 클래스의 모든 콤보에 **같은 행을 복사**해 1326 으로 전개하고 `chart_set.resolution='169'` 로 기록한다. 뷰어의 콤보 패널은 `resolution='169'` 면 "클래스 해상도 차트 — 콤보별 값은 동일" 을 표시한다 (가짜 정보 금지).

### 3.3 EV 기준점 (Phase -1 MAJOR 5)
- `ev[a][c]` = **노드 시점 이후** 히어로 스택의 기대 변화(bb). 노드 이전에 투입한 칩(블라인드·앤티·이전 레이즈)은 매몰 = 0. 따라서 **Fold 의 EV 는 항상 정확히 0** 이다. 예: HU 10bb, SB 가 루트에서 `A` → BB 폴드 시 +1.5 (자기 0.5 + BB 1.0 을 얻음), BB 콜 시 `20·eq − 9.5`.
- 파일의 `evBasis` 가 이 값(`"stack_delta_from_node"`)이 아니면 임포트 거부. 다른 기준(예: "총 스택 기대값")을 쓰는 외부 파일은 어댑터가 변환한 뒤 이 값을 붙인다. 변환 없이 라벨만 바꾸는 것은 금지.
- EV 는 노드 단위로 있거나 없다 (`ev` 가 있으면 모든 액션·모든 콤보). `chart_set.has_ev` = 모든 노드에 EV 가 있을 때만 1. 일부만 있으면 임포트 거부 (P3 채점이 `graded_by` 를 차트셋 단위로 정하기 위해).

### 3.4 도달 레인지 (reach range) 파생 규칙
```
reach(set, "", pos)[c] = 1                                  (모든 pos, 모든 c)
reach(set, seq+a, pos)[c] = reach(set, seq, pos)[c] × strategy(seq)[a][c]   if pos == hero_pos(seq)
                          = reach(set, seq, pos)[c]                           otherwise
```
- 포지션 간 카드 제거는 **적용하지 않는다** (각 포지션의 reach 는 독립 f32[1326]). 트레이너(P3)가 히어로 콤보를 샘플할 때 `reach_hero` 만 쓰고, 포스트플랍 입력(P5)에서 두 레인지를 동시에 쓸 때 `removeBoard`/충돌 콤보 제외를 그때 한다.
- 경로상 노드가 DB 에 없으면(부분 트리) `reach` 는 `undefined` 가 아니라 **에러** (`MissingNodeError(seq)`). API 는 404 `MissingNode`.
- 폴드한 포지션의 reach 는 폴드 액션의 전략을 곱한 값 그대로 남긴다 (질의는 가능하되 뷰어는 "folded" 로 표시).

### 3.5 169 표시 집계 (뷰어)
셀 `h` 의 액션 `a` 빈도 = `Σ_{c∈h} reach[c]·strategy[a][c] / Σ_{c∈h} reach[c]`. 분모 0 → 셀은 "not in range" (dim, 레이어 없음). 이 값은 표시에만 쓴다.

## 4. 스키마와 저장소 (`packages/preflop`)

### 4.1 DDL (`schema.sql` 을 문자열 상수로, `migrate()` 가 `user_version` 으로 관리)
```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

CREATE TABLE chart_set (
  id            INTEGER PRIMARY KEY,
  name          TEXT    NOT NULL UNIQUE,
  game_type     TEXT    NOT NULL CHECK (game_type IN ('cash','mtt','sng')),
  positions     TEXT    NOT NULL,   -- JSON string[] 액션 순서. 6max ["UTG","HJ","CO","BTN","SB","BB"], HU ["SB","BB"]
  blinds        TEXT    NOT NULL,   -- JSON {pos,amount}[] (스트래들 = 항목 추가). PreflopConfig.blinds 그대로
  ante          TEXT    NOT NULL,   -- JSON PreflopConfig.ante 그대로
  stack_bb      REAL    NOT NULL CHECK (stack_bb > 0),
  rake          TEXT    NOT NULL,   -- JSON {"mode":"none"} | {"mode":"pot","pct":0.05,"capBb":3,"noFlopNoDrop":true}
  resolution    TEXT    NOT NULL CHECK (resolution IN ('169','1326')),
  has_ev        INTEGER NOT NULL CHECK (has_ev IN (0,1)),
  ev_basis      TEXT    NOT NULL CHECK (ev_basis IN ('none','stack_delta_from_node')),
  source        TEXT    NOT NULL,   -- JSON 5.2 의 source 객체. 빈 객체/빈 name 금지 (CHECK (json_extract(source,'$.name') <> ''))
  format_version INTEGER NOT NULL,  -- 임포트한 ggto-json 의 version
  content_hash  TEXT    NOT NULL UNIQUE,  -- sha256(정규화 ggto-json, 5.4)
  imported_at   INTEGER NOT NULL    -- unix ms
) STRICT;

CREATE TABLE pf_node (
  id            INTEGER PRIMARY KEY,
  chart_set_id  INTEGER NOT NULL REFERENCES chart_set(id) ON DELETE CASCADE,
  action_seq    TEXT    NOT NULL,   -- '' = 루트
  hero_pos      TEXT    NOT NULL,   -- 상태 기계로 검증된 값 (조회 편의용 비정규화)
  pot_bb        REAL    NOT NULL,
  actions       TEXT    NOT NULL,   -- JSON string[] 정규 토큰
  strategy      BLOB    NOT NULL,   -- zstd(f32 LE [n_actions][1326])
  ev            BLOB,               -- zstd(f32 LE [n_actions][1326]) 또는 NULL
  UNIQUE (chart_set_id, action_seq)
) STRICT;
-- UNIQUE 가 인덱스를 만든다. 별도 idx_pf_lookup 을 만들지 않는다 (Phase -1 MINOR).
```
`user_version = 1`. 마이그레이션 프레임워크는 만들지 않는다 — `migrate(db)` 는 `user_version` 이 0 이면 DDL 실행, 1 이면 통과, 그 외면 throw.

### 4.2 타입 (`@ggto/preflop` 공개)
```ts
export interface ChartSetMeta {
  id: number; name: string; gameType: 'cash'|'mtt'|'sng';
  config: PreflopConfig;                 // positions/blinds/ante/stack 를 core 타입으로 재조립
  rake: Rake; resolution: '169'|'1326'; hasEv: boolean; evBasis: 'none'|'stack_delta_from_node';
  source: ChartSource; formatVersion: number; contentHash: string; importedAt: number;
}
export interface NodeMeta { seq: string; heroPos: string; potBb: number; actions: string[]; hasEv: boolean }
export interface NodeData extends NodeMeta { strategy: Float32Array[]; ev: Float32Array[] | null }  // 인덱스 [a] → 1326
export type Rake = { mode: 'none' } | { mode: 'pot'; pct: number; capBb: number; noFlopNoDrop: boolean };
export interface ChartSource { kind: 'generated'|'solver'|'manual'|'file'; name: string; version?: string; url?: string; params?: Record<string, unknown>; note?: string; license?: string }
```

### 4.3 `ChartRepository` (인터페이스 뒤에 두어 교체 가능하게 — Phase -1 결정)
```ts
export interface ChartRepository {
  listSets(): ChartSetMeta[];
  getSet(id: number): ChartSetMeta | null;
  listNodes(setId: number): NodeMeta[];               // 블롭 없음. 트리 스켈레톤
  getNode(setId: number, seq: string): NodeData | null;
  reach(setId: number, seq: string, pos: string): Float32Array;   // 3.4. MissingNodeError
  importSet(doc: GgtoJson, opts: { source?: 'file'|'generated' }): { id: number; nodes: number; skipped: boolean };  // 단일 트랜잭션. content_hash 중복 → skipped
  deleteSet(id: number): void;
  close(): void;
}
export function openRepository(path: string | ':memory:'): ChartRepository;
```
`opts.source` 의 의미 (R2): `'generated'` 를 주면 `doc.source.kind === 'generated'` 를 요구하고 아니면 `ChartValidationError` (생성기가 자기 출력을 잘못 라벨링하는 것을 막는다). `'file'`/생략은 검사 없음. **`id` 는 `AUTOINCREMENT` 가 아니다** (`INTEGER PRIMARY KEY` = max(rowid)+1): 마지막 행을 지우고 다시 넣으면 같은 id 가 나온다. 영구 식별자는 `content_hash` 다 — P3 의 기록은 `content_hash` 를 저장하고 `id` 는 API 핸들로만 쓴다.
`importSet` 은 **전부 검증한 뒤** `BEGIN` → 삽입 → `COMMIT`. 검증 실패는 `ChartValidationError { path: string; reason: string }[]` 를 전부 모아 한 번에 throw (첫 오류에서 멈추지 않는다). 검증 목록은 6.2.

```jsonc
      "ev":       { "AA": [0,1.93], /* ... */ }
    },
    { "seq": "A", "actions": ["F","C"], "strategy": { /* 169 */ }, "ev": { /* 169 */ } }
  ]
}
```
- `resolution: "169"` → `strategy`/`ev` 는 **169 키 전부**를 가진 객체, 키는 core `handClassName` (`AA`,`AKs`,`AKo`). 값은 길이 `actions.length` 배열.
- `resolution: "1326"` → 키는 콤보 문자열 `formatCard(hi)+formatCard(lo)` (`AsKh`, hi>lo 정규), **1326 키 전부**. 인덱스 배열이 아니라 키인 이유: 파일이 P0 인덱스 규약에 결합되지 않게.
- 숫자는 JSON number. f32 로 저장되므로 임포터가 `Math.fround` 한다.
- 노드 순서 무관. `seq` 중복 → 거부. 루트 `""` 필수.
- `version` 은 정수. 임포터는 `1` 만 받는다. 알 수 없는 최상위 필드는 **거부** (오타로 조용히 무시되는 것을 막는다).

### 5.2 `source` (필수)
`kind`: `generated`(우리 생성기) | `solver`(사용자 소유 솔버 출력) | `manual`(손으로 옮김) | `file`(타인이 배포한 파일). `name` 필수. `file`/`solver` 는 `url` 또는 `version` 중 하나 필수, `license` 권장. 임포터는 `source` 를 검사만 하고 **판단하지 않는다** — 판단은 7.2 의 규칙을 사람이 한다.

### 5.3 코덱 (`@ggto/preflop`)
`parseGgtoJson(text: string): GgtoJson` (구조·타입·키 완전성 검사, 도메인 검증은 6.2), `formatGgtoJson(doc): string` (5.4 정규화 후 직렬화), `expandTo1326(doc)`, `toGgtoJson(set: ChartSetMeta, nodes: NodeData[]): GgtoJson` (익스포트 — 왕복 테스트용).

### 5.4 정규화와 `content_hash`
`content_hash = sha256(formatGgtoJson(doc))` 이고 정규화는: 키 사전순, 노드 `seq` 사전순, `strategy`/`ev` 키 사전순, 숫자는 `Math.fround` 후 `String()`, 공백 없음. **(R2 명확화) `Math.fround` 는 문서의 모든 숫자에 적용한다** (`strategy`/`ev` 뿐 아니라 `config.stack`, `blinds[].amount`, `rake.pct` 등도). 정규화 문자열은 **해시 입력으로만** 쓰이고, DB 에는 원본 f64 가 저장된다 (`stack_bb REAL`). 따라서 `rake.pct: 0.05` 가 해시 입력에서 `0.05000000074505806` 로 보이는 것은 의도된 동작이며, f32 ULP 아래에서만 다른 두 문서가 같은 해시를 받는 것도 의도다 (포커에서 의미 없는 차이). 익스포트 → 재해시는 항등이어야 한다 (6.4 왕복 테스트). `imported_at` 은 해시에 안 들어간다. **같은 파일을 두 번 임포트하면 두 번째는 `skipped: true`**.

## 6. 임포터 CLI (`tools/chart-import`)

### 6.1 사용
```
node tools/chart-import/dist/main.js --db data/ggto.db [--format ggto-json] [--dry-run] [--replace] <file.json>...
```
- `--format`: P2 는 `ggto-json` 만 (기본값). 다른 값 → exit 2 "unsupported format".
- `--dry-run`: 검증만, DB 열지 않음.
- `--replace`: 같은 `name` 의 차트셋이 있으면 삭제 후 삽입 (`content_hash` 가 같아도).
- 출력: 파일당 한 줄 JSON `{"file":…,"ok":true,"id":3,"nodes":2,"skipped":false}` 또는 `{"file":…,"ok":false,"errors":[{"path":"nodes[1].strategy.AKs","reason":"row sums to 0.98"}]}` + 사람용 줄. 하나라도 실패하면 exit 1. **파일 단위 원자성** (한 파일 실패가 다른 파일 임포트를 막지 않는다).

### 6.2 검증 (전부 `@ggto/preflop` 에 있고 CLI 는 호출만 한다)
1. 구조 (5.1): 필드 존재/타입, 알 수 없는 필드, `version === 1`, `source.name` 비어 있지 않음.
2. `config` 는 core `preflopState(config, [])` 가 `PreflopConfigError` 를 안 던져야 한다.
3. 각 노드: `parseActionSequence(seq)` 성공 (루트 제외), 스트리트가 1개, 상태 기계로 재생 시 `IllegalActionError` 없음, **`isTerminal === false`** (터미널 노드는 전략이 없다), **각 `actions` 토큰을 `preflopState(config, prefix + [token])` 이 `IllegalActionError` 없이 받아들임** (R2: `legalActions` 는 금액 후보로 `minRaiseTo` 하나만 열거하므로 부분집합 검사는 `R3` 같은 정상 차트를 거부한다 — 리뷰어가 `R2/R2.5/R3/R9.5/A` 수용, `R10`(=A 여야 함)/`R1.5`/`B2`/`X` 거부를 확인), 중복 없음, 길이 ≥ 1.
4. `strategy` 키 완전성 (169 또는 1326 전부, 여분 키 없음), 행 길이 = `actions.length`, 값 ∈ [0,1], 행 합 ∈ [1−1e-4, 1+1e-4].
5. `ev`: 있으면 키·길이 동일, 유한수. `evBasis` 가 `stack_delta_from_node` 이고 **`F` 열은 정확히 0** (3.3 의 정의를 파일이 지켰는지 확인하는 가장 싼 검사). 노드 중 일부만 `ev` 가 있으면 거부.
6. 트리 폐쇄성 **경고** (거부 아님): 노드의 액션 `a` 로 만든 `seq+a` 가 비터미널인데 파일에 없으면 `warnings[]` 에 기록. `--strict` 로 거부로 승격 가능.
7. 루트 `""` 존재.

### 6.3 어댑터 경계
`Adapter = (bytes: Uint8Array, opts) => GgtoJson`. `ggto-json` 어댑터는 항등 + 파싱. **다른 포맷 어댑터는 실제 샘플 파일이 레포에 (`tools/chart-import/fixtures/`) 들어올 때 그 파일과 함께 작성한다.** 샘플 없는 어댑터는 검증 불가하므로 P2 에서 쓰지 않는다.

### 6.4 필수 테스트 (`packages/preflop/test`, `:memory:`)
- 왕복: 7.1 생성기 출력 → `importSet` → `getNode` → `toGgtoJson` → `formatGgtoJson` 이 원본 정규화 문자열과 **바이트 동일**.
- 169 전개: `resolution:'169'` 문서 임포트 후 `handClassCombos(h)` 의 모든 콤보 행이 동일, `resolution` 컬럼 `'169'`.
- 검증 실패 8종 각각 1개 이상: 합 0.98 / 값 1.2 / 키 누락(`72o` 없음) / 여분 키(`AKx`) / 불법 시퀀스(`R2.50`) / 불법 액션(HU 10bb 루트에서 `R25`) / `actions` 에 합법 아닌 토큰(`X` 루트) / 터미널 노드(`F`) / `F` 열 EV ≠ 0 / `source.name` 빈 문자열 / 알 수 없는 필드. **에러가 전부 모여서** 한 번에 오는지 (2개 결함 파일 → 2개 에러).
- 원자성: 노드 2개 중 하나가 불량 → 임포트 후 `listSets()` 비어 있음.
- 중복: 같은 문서 두 번 → `skipped: true`, 행 수 불변. `--replace` → id 바뀌고 노드 수 동일.
- reach: HU 시드에서 `reach(id,"A","SB")` = 루트 SB 전략의 `A` 열, `reach(id,"A","BB")` 전부 1, `reach(id,"A-C","BB")` = BB `C` 열, `reach(id,"F","SB")` = `F` 열 (질의 가능). `reach(id,"A-R3","SB")` → `MissingNodeError`.
- 블롭: `strategy` 컬럼을 직접 `SELECT` 해 `zstdDecompressSync` → `Float32Array` 가 `getNode` 결과와 원소 동일 (코덱을 우회한 검증).
- CLI (`tools/chart-import/test`): 자식 프로세스로 `--dry-run` 정상/불량, exit 코드, JSON 한 줄 형식. 임시 DB 파일에 실제 임포트 후 `openRepository` 로 읽기.

## 7. 시드 차트

### 7.1 자체 생성 (1순위, P2 DoD 의 기준 시드) — `tools/chart-gen`
**HU 푸시/폴드 내시 균형** (SB: `A`/`F`, BB: `C`/`F`). 스택 {5, 8, 10, 12, 15, 20}bb, `blinds SB 0.5 / BB 1`, 앤티 없음, 레이크 없음. 결과는 `resolution:'169'`, **EV 포함** (`has_ev=1`) — 그래서 P3 가 EV-loss 채점을 실제 데이터로 시작할 수 있다.

- **에퀴티 표**: `equity169.json` = 169×169 클래스 대 클래스 프리플랍 에퀴티 (카드 제거 반영). 계산은 core `equityRangeVsRange(parseRange(A), parseRange(B), [], {mode:'monte-carlo', samples: **200_000** (R2: 50k 에서 AKo-QQ 가 seed 별 최대 0.63%p 흔들려 게이트 초과), seed})` 를 **14,196 비대각 쌍**에 대해 (R2: 대각선 `eq(h,h)` 는 매치업 집합이 교환 대칭이므로 **정확히 0.5** — 샘플링하지 않는다) — seed 는 `sha32(A+"|"+B)` 처럼 쌍에서 결정적으로. 예상 10분. 결과 파일(약 250KB)을 `tools/chart-gen/data/equity169.json` 에 **커밋**하고 `{samples, seedRule, coreVersion, sha256}` 메타를 같이 둔다. `npm run gen:equity` 로 재생성 가능. 리뷰어 검사: Phase -1 전수 표의 AA-KK 81.946 / AKs-22 49.893 / AKo-QQ 43.242 / 72o-AA 11.800 이 MC 표에서 **±0.5%p** 안에 있어야 한다 (200k 에서 SE ≈ 0.11%p, 14,196 쌍 중 최대 오차는 ~4σ ≈ 0.45%p 로 예상 — R1 실측 30쌍 최대 0.28%p, 행 단위 최대 0.34%p). **알려진 한계**: 이 노이즈는 경계 핸드의 EV 를 ~1e-3bb 흔든다 (R1 실측 84s@8bb −0.0012 → 정확 −0.0024). P3 채점 임계(0.05bb) 보다 두 자리 작으므로 P2/P3 에서는 감수하고, 정확 표(슈트 정규형 중복 제거로 쌍당 1~7회 전수 hvh, 총 비용은 MC 와 같은 ~20분)는 P4 이후 개선 항목.
- **솔브**: 169 클래스 × 2 정보집합. 알고리즘 자유(CFR+ / regret matching / fictitious play) 단 **exploitability 를 계산해 파일 `source.params.exploitabilityBb` 에 기록**하고 게이트 `< 0.005 bb` (R2: 채택된 것은 CFR+ 5,000 반복, 실측 exploitability 2e-8 ~ 1.4e-7bb). 클래스 가중치는 6/4/12 (콤보 수) — 169 로 푸는 것이 정확한 이유는 프리플랍 HU 에서 슈트 순열 대칭 때문이며, 이 사실을 생성기 README 한 줄로.
- **EV**: 3.3 기준. SB `A` 의 EV[h] = Σ_v p(v|h)·[ fold_v·1.5 + call_v·(2S·eq(h,v) − (S−0.5)) ], `F` = 0. BB `C` 의 EV[h] (노드 `A`) = Σ_v p(v|h, v jams)·(2S·eq(h,v) − (S−1)), `F` = 0. `p(v|h)` 는 카드 제거 반영 (클래스 콤보 수에서 `h` 와 충돌하는 콤보 제외).
- 성질 게이트 (테스트): (a) 모든 스택에서 AA 는 SB `A` 100%, BB `C` 100%. (b) 스택이 줄수록 SB 잼 콤보 합(1326 가중)이 **단조 증가**. (c) 20bb 에서 72o 잼 0%. (d) exploitability 게이트. (e) 같은 입력 → 바이트 동일 출력 (결정적). 알려진 공개 푸시/폴드 표와의 수치 대조는 **하지 않는다** — 출처·레이크·모델이 제각각이라 기준이 될 수 없다. 리뷰어가 독립 구현으로 재계산해 대조한다.
- 출력: `data/charts/hu-pushfold-<stack>bb.json` 6개 + `npm run seed` 가 임포트. `source = {kind:'generated', name:'ggto chart-gen push-fold', version, params:{stack, equityTable sha256, iterations, exploitabilityBb}, license:'self'}`.

## 8. 서버 API (`@ggto/server`, `@ggto/protocol` 타입 추가)

| 메서드/경로 | 응답 |
|---|---|
| `GET /api/charts` | `{ sets: ChartSetMeta[] }` |
| `GET /api/charts/:id` | `ChartSetMeta & { nodes: NodeMeta[] }` (트리 스켈레톤). 없으면 404 `NotFound` |
| `GET /api/charts/:id/node?seq=` | `NodeMeta & { strategy: number[][]; ev: number[][] | null; reach: number[] }` — `strategy[a]` 길이 1326, `reach` 는 히어로 포지션의 3.4 값. **P2 는 JSON number[][]** (P1 3.3 과 같은 결정 — 5×1326 은 ~60KB, 디버깅 가능. octet-stream 은 P5 솔버 노드부터). `seq` 없음 → 루트. 파싱 실패 → 400 `ActionSyntaxError`. 노드 없음 → 404 `MissingNode` |
| `GET /api/charts/:id/range?seq=&pos=` | `{ pos, seq, weights: number[] }` 1326. `pos` 가 config 에 없으면 400 `BadRequest`. 경로 노드 누락 → 404 `MissingNode` |

- `seq` 는 쿼리 문자열이므로 `+` 가 없다 (P0 4.7 문법에 `+` 없음). `-`/`.` 는 그대로. 서버는 `decodeURIComponent` 로 읽는다 (P1 R1 MAJOR 1 교훈 — Hono 의 `c.req.query()` 가 `+` 를 공백으로 바꾸는지 확인하고 보고. **R1 실측 (hono 4.13.7): 바꾼다** — `?seq=a+b` → `'a b'`. 그래서 서버의 모든 쿼리 파싱은 `queryParam`(`decodeURIComponent`) 으로 통일한다). **(R2) 깨진 퍼센트 시퀀스(`?seq=%zz`)의 `URIError` 는 400 `BadRequest` 다** — 500 이 아니다 (R1 실측 500 + 스택 로그. `web/src/lib/defaults.ts` 의 `urlParam` 이 이미 하는 것과 같은 처리).
- 저장소는 `createApp({ repo })` 로 주입. 테스트는 `:memory:` 저장소에 7.1 시드를 넣고 인프로세스 요청.
- 에러 매핑 `errors.ts` 에 `MissingNodeError → 404 'MissingNode'`, `ChartValidationError → 400` 추가 (임포트 API 는 P2 에 없지만 매핑은 미리).
- `smoke.mjs` 추가 항목: `GET /api/charts` 200 (`data/ggto.db` 가 없으면 빈 배열 — 503 아님), 시드가 있으면 `/api/charts/1/node` 의 `strategy[0].length === 1326`.

## 9. 웹 뷰어 (`/charts`)

```
┌──────────────────────────────────────────────────────────────────────────┐
│ GGTO — Charts        [HU push/fold 10bb (generated) ▾]   source: generated│
│ 포지션:  [SB] [BB]                (탭 = config.positions, 활성 = hero_pos)│
│ 라인:  root › A                   (브레드크럼 = 경로상 노드, 클릭 이동)   │
│ 다음:  [F] [C]                    (현재 노드 actions, 클릭 = seq+a 로 이동)│
├────────────────────────────┬─────────────────────────────────────────────┤
│ RangeGrid (액션 누적 색)    │ 선택: AKs (4 combos)  reach 100%             │
│ ■ A 빨강  ■ F 회색          │ A   100%   EV +1.42bb                        │
│ [strategy] [reach]          │ F     0%   EV  0.00bb                        │
│                             │ 콤보: AsKs A 1.00 / AhKh A 1.00 … (169 해상도 │
│ hover: AKs · A 100% · +1.42 │ 차트 — 콤보별 값 동일)                       │
└────────────────────────────┴─────────────────────────────────────────────┘
```
- **포지션 탭**: `config.positions` 순서. 활성 탭 = 현재 노드 `hero_pos` (읽기 전용 표시). 다른 탭 클릭 = "그 포지션이 다음에 행동하는 가장 가까운 노드" 로 이동하지 **않는다** (모호함). 탭은 표시 + `reach` 모드에서 "이 포지션의 도달 레인지" 를 그리는 선택자 역할만.
- **브레드크럼**: `seq` 를 `-` 로 쪼갠 접두들. 각 접두는 노드가 있을 때만 링크.
- **격자**: `RangeGrid` 계약 유지(P1 4.3). `CellModel` 에 `layers: readonly { key: string; color: string; fraction: number }[]` 와 `inRange: boolean` 추가, P1 weight 모드는 `layers=[{key:'weight', color:green, fraction:fill}]` 로 표현 (동작 불변, `RangeGrid.test.tsx` 의 `fillRect === 169 + filled` 는 레이어 수로 바뀐다 — 그 테스트를 갱신하라). 색 배정: 액션 종류별 고정 (`F` slate, `X` sky, `C` emerald, `B*`/`R*` 는 amber → red 사이즈 순, `A` crimson). 범례 표시.
- `strategy` 모드: in-range 셀은 높이 1 을 액션 빈도로 분할(3.5). `reach` 모드: P1 과 같은 단일 녹색 fill = `Σ reach / comboCount`.
- 호버 상태줄: `AKs · A 100% +1.42bb · F 0% +0.00bb` (+ `EV` 는 `has_ev` 일 때). **(R2) 캔버스 툴팁은 없다** — P1 R2 MINOR 5 에 따라 제거했고 상태줄이 유일한 호버 표시다 (`formatChartCellSummary`). P3 트레이너도 같은 규칙.
- 우측 패널: 클래스 액션표 (빈도 = 3.5, EV = reach-가중 평균) + 콤보표 (`handClassCombos`, 콤보별 액션 빈도·EV). `resolution='169'` 안내문.
- 상태: zustand 에 `chartSetId`, `seq`, `viewMode`, `selectedClass`, `hoveredClass`. 서버 데이터는 TanStack Query (`['charts']`, `['chart', id]`, `['node', id, seq]`). URL 동기화: `/charts?set=1&seq=A` 를 마운트 시 읽고(`decodeURIComponent`, P1 4.1 규칙) 이동 시 `history.replaceState`.
- 필수 테스트 (`web/test`): 셀 집계 3.5 를 1326 에서 손으로 재계산해 169 셀 대조 (`reach` 0 클래스 → `inRange=false`), 레이어 fraction 합 ≤ 1+1e-6, 브레드크럼 링크가 존재 노드만, 액션 버튼 클릭 → 다음 fetch 가 `seq=A`, `reach` 모드 전환 시 fill = P1 규칙, 응답은 core + 7.1 생성기 출력으로 만든다 (가짜 배열 금지).

## 10. 벤치 (P0 5절 형식, `packages/preflop/bench`)
`importSet` 6 시드 (12 노드) < 500ms, `getNode` 1000회 < 300ms (zstd 해제 포함), `reach` 깊이 2 × 1000회 < 300ms. plain node.

**(R3) 부하 인지 게이트 — 절대 시간 예산은 그대로 두고, 예산 *집행* 을 머신 부하로 조건화한다.** 근거 (P2 R2 리뷰 4절): 같은 코드가 LoadPercentage 9 에서 getNode 137 / reach 102ms, 55~85 에서 162~186 / 122~134ms, 90~100(사용자 게임 중) 에서 304~510 / 330~412ms 로 잰다. P1 R2 와 P2 R2 두 번 연속 "회귀 아님, 머신 부하" 판정이 났으므로 게이트 설계가 틀린 것이다. 예산을 올리는 것(600ms 제안)은 기각 — 유휴 137ms 대비 300ms 는 이미 2.2배 여유라 **2배 회귀(274ms)를 지금도 못 잡고**, 600 이면 4배 회귀까지 통과한다. 포화 상태에서는 어떤 유한 예산도 안전하지 않다(실측 3.7배). `ci` 에서 떼는 것도 기각 — 벤치는 `check` 로 결과 정확성도 단언하고, 매 `ci` 로그의 수치가 이 프로젝트의 유일한 성능 이력이다.

규칙:
1. 벤치 스크립트가 **스스로 부하를 잰다**: 실행 시작·종료 시점에 `os.cpus()[i].times` 를 합산해 `load = Δ(user+nice+sys+irq) / Δ(전체)` (전 코어, 자기 자신 포함 — 6코어에서 단일 스레드 벤치는 ≈17%p 를 스스로 보탠다). 결과 JSON 에 `load` (0~1) 와 `enforced` (boolean) 를 넣고 사람용 줄에도 `load NN%` 를 찍는다. `Get-CimInstance` 수동 보고는 폐지 (Windows 전용이고 1초 스냅샷이라 벤치 구간과 어긋난다). `process.cpuUsage()` 는 쓰지 않는다 — Windows 에서 15.6ms 로 양자화돼 (R2 실측 94/110/141ms 로 튐) 정규화 수단이 못 된다.
2. **정확성 `check` 실패는 부하와 무관하게 exit 1.**
3. 예산 초과는 `load ≤ 0.60` 일 때만 exit 1. 그 위에서는 `OVER (not enforced: load 87%)` 로 찍고 exit 0 (`enforced:false`). `--strict` 플래그는 부하와 무관하게 집행 (리뷰어·DoD 용). 임계 0.60 은 R2 실측(측정치 52~68% ≈ CIM 35~52 에서 wall ≈ 유휴 +10%) 에 맞춘 보수적 값이고, 이력이 쌓이면 올릴 수 있다.
4. `measure` 는 warmup 2, runs 5 의 최솟값 (3 → 5). 최솟값이 예산 게이트에 맞는 통계량이다.
5. 구현은 core·preflop 벤치가 공유하는 하네스 하나(`packages/core/bench/harness.mjs` 권장: `measure`, `sampleLoad`, `runCases`) 로. 두 스크립트가 각자 복사하지 않는다.
6. 예산 수치는 바꾸지 않는다 (500/300/300). 유휴 기준값 기록: getNode 137.4 / reach 101.6 (CIM 9, R1), 145.5 / 120.3 (CIM 39~49, R2 fresh), 144.3 / 93.3 (`load 0.599`, R3 fresh). 300 은 기준 대비 2.2배라 **≥2.2배 회귀만 잡는 게이트** 임을 명시한다. 1.5배(getNode 210 / reach 160) 로 조이는 것은 유휴 기준값이 세 라운드 이상 안정된 뒤 P3 이후에 결정.
7. **(R4) JSON 필드 확정**: `suite`, `node`, `load`, `loadThreshold`, `enforced`, `strict`, `results[]{name, ms, budgetMs, ok, withinBudget, correct}`, `ok`. **`ok` 는 집행과 무관한 사실값** (`정확성 실패 0 && 예산 초과 0`) 이고 exit 코드는 집행 결과다 — 미집행 OVER 가 있으면 `ok:false` 와 exit 0 이 공존하며 이것이 의도다 (로그가 사실을 말한다). 자기 기여 1/ncpu 보정과 게이트 논리 테스트는 P3 이월 (P2 R3 MINOR 1·2).

## 13. 리뷰어가 추가로 돌릴 것
- 독립 구현 푸시/폴드 솔버(리뷰어 스크래치)로 6 스택의 SB 잼 레인지·BB 콜 레인지·EV 를 재계산해 생성 파일과 대조. **(R2) 게이트는 전략 L∞ 가 아니다** — HU 푸시/폴드 균형은 유일하지 않다: 무차별 클래스(|EV| ≈ 0)의 빈도는 구간 전체가 균형이고(R1 실측: 5bb BB 95s 를 0~1 어디에 둬도 NashConv ≤ 3.3e-6, 반면 순수 클래스 K2o 를 0.9 로만 옮겨도 1e-4), 제로섬이라 두 해의 교차쌍도 균형이다(interchangeability). 판정 기준: (a) 리뷰어의 독립 best response 로 계산한 파일 전략의 exploitability < 1e-5 bb (파일 기록값과 같은 자릿수), (b) 두 해의 전략 L∞ ≥ 0.02 인 클래스는 모두 파일 EV `|EV| < 1e-3 bb` (무차별) 이어야 하고 그 클래스를 어느 쪽 값으로 바꿔도 NashConv < 1e-5, 그 외 클래스는 L∞ < 0.02, (c) 1326 가중 집계 레인지 % 차이 < 0.2%p, (d) 게임값(SB 한 판 기대값) 차이 < 1e-4 bb, 각 클래스 EV L∞ < 0.05 bb (채점 임계 이하는 무의미).
- `equity169.json` 의 무작위 20쌍 + 고정 10쌍을 **core 전수 hvh 로 정확히** 재계산 → ±0.5%p (R1: 30쌍 최대 0.28%p).
- 불량 ggto-json 퍼즈 30개(무작위 결함 주입) → 전부 exit 1 + DB 불변.
- `/api/charts/:id/node` 응답의 `strategy` 를 `Float32Array.from` 해서 DB 블롭 직접 해제값과 원소 비교.
- 뷰어 픽셀: 셀 레이어 높이를 3.5 로 계산한 값과 캔버스 샘플 대조 (P1 방식).
- `seq` 에 `%2D`, 공백, `+` 를 넣은 URL 로 서버가 어떻게 응답하는지.
