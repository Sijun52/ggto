## 0. 목표와 완료 그림

`npm run build && npm start` 후 브라우저에서 `http://localhost:7777/?range=22%2B%2CA2s%2B%2CKTo%2B` 를 열면:
1. 서버가 `web/dist` 의 SPA 를 준다.
2. SPA 가 `POST /api/range/parse` 로 `"22+,A2s+,KTo+"` 를 보내고 **1326 가중치**를 받는다.
3. 브라우저가 `@ggto/core` 의 `toHandClassView` 로 169 집계를 만들어 `RangeGrid` (Canvas 13×13) 를 그린다. 셀 호버 → 클래스명/가중치/콤보 수, 셀 클릭 → 우측 패널에 4/6/12 콤보 각각의 가중치.
4. 입력 상자의 텍스트를 바꾸고 제출하면 격자가 바뀐다. 잘못된 텍스트(`T9s+`, `AKx`)는 서버의 `RangeSyntaxError` 메시지가 그대로 화면에 뜬다.

**만들지 않는 것**: DB, 차트 임포트, 트레이너, 솔버, 액션 트리 UI, 레인지 편집기(텍스트 입력만), 인증. `pf_node`/`chart_set` 스키마는 P2.

## 2. 계층 경계 (grep 으로 검사한다)

- `web/src` 는 `@ggto/core`, `@ggto/protocol`, react 계열, zustand, tanstack 만 import. `packages/server` 를 import 하지 않는다.
- `packages/server/src` 는 `@ggto/core`, `@ggto/protocol`, 프레임워크, `node:*` 만. React/DOM 없음.
- **어느 패키지도 `@ggto/core/internal` 을 import 하지 않는다** (P0 DoD 6).
- `packages/protocol/src` 는 import 가 없다 (타입 전용). `@ggto/core` 의 타입을 재선언하지 말고 필요하면 `import type` 만 허용.
- 169 인덱스를 입력으로 받아 **계산**하는 함수는 어디에도 없다. `lib/grid.ts` 는 1326 → 169 **표시 모델** 변환만 한다 (P0 DoD 5 와 같은 원칙).
- `web/src` 에서 핸드 이름 리터럴(`"AA"`, `"AKs"` 등)과 레인지 텍스트 리터럴은 **`DEFAULT_RANGE_TEXT` 상수 하나**(값 `"22+,A2s+,KTo+"`)만 허용. 격자 라벨은 `handClassName()` 으로 만든다. 리뷰어가 `grep -rnE "'[AKQJT98765432]{2}[so]?'" web/src` 로 검사한다 (테스트 제외).

## 3. 서버 (`@ggto/server`)

### 3.1 공통
- 포트: `PORT` 환경변수, 기본 **7777**. 바인드 `127.0.0.1` (로컬 앱. `0.0.0.0` 금지).
- 요청 본문 상한 64KB. 초과 → 413 `PayloadTooLarge`. (R1: 본문을 전부 읽은 뒤 크기를 재는 구현을 P1 에서 허용한다 — 127.0.0.1 바인드 + JSON 전용. P2 에서 octet-stream 엔드포인트가 생기면 스트림에서 끊는다.)
- JSON 응답. 에러 봉투 (**전 엔드포인트 공통**):
  ```ts
  { error: { code: string; message: string } }
  ```
  `code` 는 도메인 에러 클래스 이름 그대로: `RangeSyntaxError`, `CardSyntaxError`, `EmptyRangeError`, `UnsupportedError`, `ActionSyntaxError` → **400**. 형식 오류(필드 누락/타입 불일치/JSON 아님) → 400 `BadRequest`. 없는 경로 `/api/*` → 404 `NotFound`. 그 외 예외 → 500 `Internal` (메시지는 `"internal error"` 고정, 스택은 서버 로그로만). `errors.ts` 의 매핑 함수 하나가 이걸 전담하고, 라우트 핸들러는 도메인 함수를 그대로 부르고 throw 를 흘려보낸다.
- 로깅: `console.error` 만, 500 일 때만. 요청 로그 미들웨어는 P1 에 넣지 않는다.
- CORS 불필요 (같은 오리진 + dev 는 Vite 프록시).

### 3.2 엔드포인트

| 메서드/경로 | 요청 | 응답 |
|---|---|---|
| `GET /api/health` | — | `{ ok: true, version: string, node: string }` (`version` 은 server package.json 의 version) |
| `POST /api/range/parse` | `{ text: string }` — 길이 ≤ 4,000 | `ParseRangeResponse` (3.3) |
| `POST /api/range/equity` | `EquityRequest` (3.3) | `EquityResponse` |
| `GET /` 및 `/api` 가 아닌 모든 경로 | — | `web/dist` 의 정적 파일. 파일이 없으면 `index.html` (SPA 폴백). `web/dist` 자체가 없으면 `/` 는 503 `{error:{code:'WebNotBuilt', message:'run npm run build'}}` — 조용히 빈 페이지를 주지 않는다 |

`POST /api/range/parse` 의미: `parseRange(text)` → 응답 `weights` 는 1326 원소, `text` 는 `formatRange(parseRange(text))` (정규형 에코). **169 값은 응답에 넣지 않는다** — 집계는 클라이언트가 `toHandClassView` 로 한다. 빈 문자열은 P0 규약대로 빈 레인지 (200, `comboCount: 0`).

`POST /api/range/equity` 의미: `hero`/`villain` 텍스트를 `parseRange`, `board` 를 `parseCards`, 양쪽에 `removeBoard` 후 `equityRangeVsRange(hero, villain, board, opts)`. 정규화는 core 가 내부에서 하는 정의(P0 4.5)를 그대로 따른다 — 서버에서 `normalize` 를 따로 부르지 않는다. `mode: 'exact'` 는 보드 3~5장에서만 (아니면 core 의 `UnsupportedError` 가 400 으로 나감). `monte-carlo` 의 `samples` 는 기본 200,000, 상한 **1,000,000** (초과 → 400 `BadRequest`). `seed` 생략 시 서버가 `Date.now()` 로 정하고 응답에 **사용한 seed 를 돌려준다** (재현용).

### 3.3 프로토콜 타입 (`@ggto/protocol`)
```ts
export interface ErrorEnvelope { error: { code: string; message: string } }

export interface HealthResponse { ok: true; version: string; node: string }

export interface ParseRangeRequest { text: string }
export interface ParseRangeResponse {
  text: string;            // 정규형 (formatRange)
  comboCount: number;      // weight > 0 콤보 수
  totalWeight: number;
  weights: number[];       // 길이 1326. float32 값을 JSON number 로 (정확: f32 → f64 → 문자열 → f32 는 항등)
}

export interface EquityRequest {
  hero: string; villain: string; board: string;          // board: "Ks7h2d" 붙여쓰기, "" 허용
  mode: 'exact' | 'monte-carlo';
  samples?: number; seed?: number;
}
export interface EquityResponse {
  hero: number; villain: number; tie: number; heroWin: number; villainWin: number;
  matchups: number;
  heroPerCombo: (number | null)[];    // 1326. NaN 은 JSON 에 없으므로 null
  villainPerCombo: (number | null)[];
  mode: 'exact' | 'monte-carlo'; samples: number | null; seed: number | null;
  board: string;                       // 정규형 에코 (formatCards)
}

export const API_LIMITS = { bodyBytes: 65536, rangeTextChars: 4000, maxSamples: 1_000_000 } as const;
export const API_ROUTES = { health: '/api/health', rangeParse: '/api/range/parse', rangeEquity: '/api/range/equity' } as const;  // R1: 허용된 상수
```
`EquityRequest.mode` 는 `export type EquityMode = 'exact' | 'monte-carlo'` 로 빼도 된다. **`seed` 는 정수 `[0, 2^32-1]`** — core `createRng` 가 `Math.trunc(seed) | 0` 으로 32비트만 쓰므로 그 밖의 값은 400 `BadRequest` (R1 확정). 서버가 정하는 seed 도 이 범위.
1326 배열의 전송 형식은 P1 에서 **JSON number[]** 로 고정한다 (Phase -1 MAJOR 4 의 octet-stream 은 P2 전략 블롭부터. 1326 개는 ~10KB 라 문제 없고, 디버깅이 쉽다). 클라이언트는 받자마자 `Float32Array.from(weights)` 로 바꾼다 — `number[]` 를 격자까지 끌고 가지 않는다 (P0 2절 규약).

### 3.4 서버 필수 테스트 (인프로세스)
- `GET /api/health` → 200, `ok: true`, `node` 가 `process.version`.
- `POST /api/range/parse {"text":"22+,A2s+,KTo+"}` → 200, `weights.length === 1326`, `comboCount === 162` (78+48+36, P0 4.3 수치), `totalWeight === 162`, `text === "22+,A2s+,KTo+"`. `weights` 를 `Float32Array.from` 해서 `parseRange("22+,A2s+,KTo+")` 와 원소 단위 완전 동일.
- `{"text":"QQ:0.5"}` → 6개 원소가 0.5, `text === "QQ:0.5"`. `{"text":""}` → 200, `comboCount 0`, `text ""`.
- `{"text":"T9s+"}` → 400, `error.code === "RangeSyntaxError"`, 메시지에 `connector`. `{"text":"AKx"}` → 400 `RangeSyntaxError`. `{}` → 400 `BadRequest`. `{"text": 5}` → 400 `BadRequest`. 본문이 JSON 이 아님 → 400 `BadRequest`. 4,001자 → 400 `BadRequest`. 70KB 본문 → 413.
- equity: `{hero:"AA", villain:"KK", board:"", mode:"monte-carlo", samples:200000, seed:1}` → `hero` 가 0.81946 ± 0.005 (P0 4.5 표), `seed === 1`, `hero + villain ≈ 1` (1e-6). 같은 요청 두 번 → **바이트 동일 응답** (시드 재현). `{..., board:"Kh7c2d", mode:"exact"}` → `hero` 가 core 의 `equityRangeVsRange` 직접 호출 결과와 1e-9 이내 (테스트 안에서 core 를 직접 불러 비교 — 서버가 인자를 바꾸지 않았는지). `board:"Kh", mode:"exact"` → 400 `UnsupportedError`. `board:"KhKh"` → 400 `CardSyntaxError`. `hero:"AsKs", board:"As7c2d"` → 400 `EmptyRangeError`. `samples: 2000000` → 400 `BadRequest`. perCombo 에서 레인지 밖은 `null`, 안은 number.
- 정적: 임시 디렉터리에 `index.html` + `assets/x.js` 를 만들어 `createApp({ webDist })` 로 띄우고 `GET /` → HTML, `GET /assets/x.js` → JS 내용, `GET /some/spa/route` → `index.html`, `GET /api/nope` → 404 JSON. `webDist` 가 없는 디렉터리면 `GET /` → 503 `WebNotBuilt`.
- 500 매핑: 테스트용으로 throw 하는 라우트를 `createApp({ testRoutes: true })` 에서만 등록해 `Internal` 봉투와 메시지 고정 확인.

## 4. 웹 (`@ggto/web`)

### 4.1 화면 (한 페이지)
```
┌──────────────────────────────────────────────────────────────┐
│ GGTO — Range                                                 │
│ [ 22+,A2s+,KTo+                              ] [Parse]      │
│ canonical: 22+,A2s+,KTo+   combos: 162 / 1326  weight: 162   │
├───────────────────────────────┬──────────────────────────────┤
│  RangeGrid 13×13 (Canvas)     │  ComboPanel                  │
│  A K Q J T 9 8 7 6 5 4 3 2    │  AKs (4 combos)              │
│ A ■ ■ ■ ■ ■ ■ ■ ■ ■ ■ ■ ■ ■   │  AsKs 1.00                    │
│ K ▨ ■ …                       │  AhKh 1.00 …                 │
│ …                             │                              │
└───────────────────────────────┴──────────────────────────────┘
```
- 초기 텍스트: URL `?range=` (있으면 **`decodeURIComponent`**) → 없으면 `DEFAULT_RANGE_TEXT`. 마운트 시 자동으로 한 번 파싱한다. **`URLSearchParams` 금지** (R1 MAJOR 1): 폼 인코딩 규칙으로 리터럴 `+` 를 공백으로 바꾸고, core 파서가 항목 뒤 공백을 허용하므로 `?range=22+,A2s+,KTo+` 가 에러 없이 `22,A2s,KTo` 로 그려진다. `location.search` 에서 `range=` 값을 직접 잘라 `decodeURIComponent` 한다 (`%2B` 와 리터럴 `+` 둘 다 `+`). 디코드 실패(`URIError`)는 `DEFAULT_RANGE_TEXT`. (R2) `range=` 가 여러 번이면 **첫 번째**가 이긴다 (`URLSearchParams.get` 관례와 동일). 키 비교는 정확 일치·대소문자 구분 (`xrange`, `RANGE` 는 무시). 해시(`#`)는 읽지 않는다. `?range=` (빈 값) 은 빈 레인지.
- Parse 버튼/Enter → `useParseRange` mutation → 성공 시 격자·요약 갱신, 실패 시 입력 상자 아래에 `error.code: message` 를 빨간 글씨로. 이전 격자는 유지한다. 유지할 격자가 없으면(첫 요청부터 실패) 격자 자리에 `data-testid="grid-placeholder"` 로 `no range to draw` (R1 반박 4 수용). 다음 성공 시 에러 문구는 사라진다.
- 요약 줄은 `data-testid="range-summary"` 에 `canonical`, `combos`, `weight` 를 텍스트로 넣는다 (스모크/리뷰어가 읽는다).
- 호버 툴팁: `클래스명 · weightSum(소수 2자리) / comboCount` — **분모는 4.2 의 `comboCount` (클래스 크기 6/4/12)** 다. `activeCombos` 가 아니다 (R1 MAJOR 2: `QsQh:0.5` 에서 `QQ · 0.50 / 1` 은 셀 fill 0.083 과 모순). 예: `AKs · 4.00 / 4`, `QQ:0.5` → `QQ · 3.00 / 6`, `QsQh:0.5` → `QQ · 0.50 / 6`. `activeCombos < comboCount` 일 때 ` · N active` 를 덧붙이는 것은 허용. (R2) 같은 텍스트가 격자 아래 **상태줄** `data-testid="hover-readout"` 에 `hover: <같은 문자열>` (비호버 시 `hover: —`) 로도 나온다 — 툴팁과 상태줄은 **같은 포매터** `formatCellSummary` 를 쓴다. 툴팁은 행 0·1 에서는 셀 아래, 그 외는 셀 위에 띄운다 (열 라벨과 겹치지 않게; 이웃 행 1개를 가리는 것은 허용). 클릭 → `ComboPanel` 에 `handClassCombos(h)` 의 각 콤보를 `formatCard(hi)+formatCard(lo)` 와 `weights[i]` (소수 2자리) 로 나열. 선택 셀은 테두리 강조.

### 4.2 `lib/grid.ts` (순수, 테스트 대상)
```ts
export interface CellModel {
  handClass: HandClassIndex;   // = row*13 + col (P0 3.3 과 동일한 인덱스. 재매핑 없음)
  label: string;               // handClassName(handClass)
  kind: 'pair' | 'suited' | 'offsuit';
  comboCount: number;          // 클래스 크기 6/4/12
  activeCombos: number;        // weight > 0 콤보 수 (view.count)
  weightSum: number;           // view.weight
  fill: number;                // weightSum / comboCount ∈ [0,1] — 셀 채움 비율
}
export function buildCells(weights: Range): CellModel[];   // 길이 169, 인덱스 = handClass
export function cellAt(x: number, y: number, size: number): HandClassIndex | null;  // 캔버스 좌표 → 셀. 밖이면 null
export function formatCellSummary(cell: CellModel): string;   // (R2) `${label} · ${weightSum.toFixed(2)} / ${comboCount}` — 툴팁·상태줄 공용
export function axisLabels(): string[];                        // (R2) 대각선 페어 이름 첫 글자 13개 (하드코딩 금지)
```
`buildCells` 는 `toHandClassView` 를 한 번 부르고 169 셀을 채운다. **`fill` 이 유일한 시각 매핑**이다 (P1 은 'weight' 모드만. 액션 색 스택은 P2).

### 4.3 `RangeGrid` 컴포넌트 계약 (P2 뷰어·P3 트레이너·P5 탐색기가 재사용)
```ts
interface RangeGridProps {
  cells: readonly CellModel[];          // 169
  size?: number;                        // px, 기본 520. devicePixelRatio 반영해 선명하게
  selected?: HandClassIndex | null;
  onSelect?(h: HandClassIndex): void;

```
- Canvas 하나. 셀 = 정사각형, 행 0 = A 위, 열 0 = A 왼쪽, 대각선 페어, **우상단 수티드, 좌하단 오프수트** (P0 3.3). 채움: 셀 배경 회색, `fill` 비율만큼 아래에서 위로 색 채움(세로 스택 — P2 에서 액션별 색으로 확장할 자리). 라벨은 항상 그린다.
- 그리기 함수 `drawGrid(ctx, cells, size, dpr, selected)` 를 별도 export 해서 컴포넌트와 분리한다 (jsdom 에서는 `getContext` 가 null 이므로 컴포넌트 테스트는 스텁 컨텍스트로 호출 여부만 본다).
- 접근성/테스트 훅: 캔버스에 `role="grid"`, `aria-label="range grid"`, 그리고 `data-selected={label}`.
- 리렌더 규칙: `cells` 참조가 바뀔 때만 다시 그린다 (`useEffect` 의존성). 호버는 별도 오버레이 상태로 처리해 169 셀을 다시 그리지 않는다.
