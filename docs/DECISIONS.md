# GGTO 결정 로그

페이즈별 스펙은 `docs/specs/P*.md`, 리뷰 전문은 `docs/reviews/` 에 있다.
이 문서는 **되돌리면 안 되는 결정과 그 근거**만 모은다. 새 페이즈에서 같은 논쟁을 반복하지 않기 위한 것이다.

| # | 결정 | 근거 | 출처 |
|---|---|---|---|
| D1 | 스택은 **하이브리드**: TS/Node 24 본체, Rust 는 P4 솔버 데몬 한정 | `wasm-postflop` 에 사전빌드 아티팩트가 **없다**(GitHub releases 비어 있음, npm 0건, crates.io 404). 오케스트레이터의 "사전빌드 wasm 존재" 전제가 사실이 아니었음. 본체까지 Rust 로 가면 P0~P3 이득이 없음 | phase-minus1 |
| D2 | 솔버는 **별도 프로세스**(stdio JSON-lines RPC), 인프로세스 링크 금지 | postflop-solver/wasm-postflop 전부 **AGPL-3.0-or-later**. 개인 로컬 사용은 의무 없으나 프로세스 경계가 배포 시 라이선스 선을 지킨다. 또한 GB 단위 솔브 결과가 상주해야 노드 lazy 조회가 가능 | phase-minus1 |
| D3 | 액션 시퀀스 구분자는 `.` 이 아니라 **`-`** (스트리트는 `/`) | `.` 은 소수점과 충돌해 `"F.F.R2.5.F"` 를 토크나이즈할 수 없음. 이 문자열이 캐시 키이자 DB UNIQUE 컬럼이라 나중에 못 바꿈 | phase-minus1 |
| D4 | 계산은 **1326 콤보**, 표시만 **169 격자**. 169 을 입력으로 받는 함수 금지 | 블로커 효과(같은 셀 안에서 콤보별로 전략이 갈림)를 표현하지 못하게 됨 | DESIGN 0.3 |
| D5 | 보드 동형 정규화는 "비대칭이면 포기" 가 아니라 **stabilizer 부분군 내 최소 보드 선택** | 분기 없는 단일 코드 경로. 대칭이면 24 순열, 완전 비대칭이면 항등. 플랍 22,100 → 1,755 (직접 전수 검증) | phase-minus1 / P0 4.6 |
| D6 | 캐시 키에는 **레인지에도** SuitMap 을 적용 | 보드만 정규화하면 서로 다른 게임이 같은 키를 받는다. P0 에 음성 테스트로 고정 | phase-minus1 |
| D7 | EV 전송은 **f32**. f16 금지 | 실측 f16 ULP = 0.0625bb (64~128bb 구간) 로 Perfect 임계 0.05bb 와 같은 크기. DESIGN 9절의 "f16 오차 ~0.001bb" 는 틀린 서술이었음 | phase-minus1 |
| D8 | 트레이너 채점은 **EV loss**. 빈도 일치 채점 금지 | GTO 가 60/40 으로 섞는 스팟에서 40% 를 골라도 EV 손실이 0 이면 정답. 빈도로 채점하면 틀린 것을 가르친다. 단 EV 없는 공개 차트는 `graded_by:'frequency'` 로 **라벨링**해 폴백 | phase-minus1 / DESIGN 6.2 |
| D9 | 액션 문자열 계약 = **히스토리 ↔ 문자열 전단사**. 포트-상태 ↔ 문자열이 아님 | `C-R2-C`(림프-레이즈-콜) 와 `R2-C`(오픈-콜) 는 포트 상태가 같아도 **다른 인포셋**이고 SB 레인지 구성이 다르다. 합치면 틀린다. transposition 은 합치지 않는다 | P0-round2 (dev 반박 수용) |
| D10 | 풀스택 레이즈는 `R<stack>` 이 아니라 **`A`** 로만 표기 | `R100` 과 `A` 가 같은 상태를 만들면 캐시 키가 중복된다. 콜 올인은 `C`. `A` 는 `stack > currentBet` 일 때만 합법 | P0-round1 MAJOR 1 |
| D11 | 커넥터 `+` (`T9s+`, `AKs+`) 는 **RangeSyntaxError** | 도구마다 의미가 다름(커넥터 런 vs 키커 런). 조용히 한쪽으로 해석하면 P2 차트 임포트에 틀린 레인지가 들어온다. 갭 2 이상(`T8s+`)은 정상 키커 런 | P0-round1 MAJOR 2 |
| D12 | 성능 게이트는 vitest 밖(`npm run bench`, plain node) | vitest/Vite SSR 변환이 import 바인딩을 네임스페이스 프로퍼티 로드로 만들어 루프마다 비용이 붙는다. 실측: 동일 코드가 vitest 125ms vs plain node 22ms. vitest 안에서 재면 런타임 아티팩트를 측정하게 됨 | P0-round2 C-6 |
| D13 | URL 쿼리 파싱에 **`URLSearchParams` 금지**. `decodeURIComponent` 직접 사용 | `URLSearchParams` 는 form-urlencoded 규칙이라 리터럴 `+` 를 공백으로 바꾼다. `?range=22+,A2s+,KTo+` 가 **에러 없이** 162콤보 → 22콤보로 바뀌고 있었음 | P1-round1 MAJOR 1 |
| D14 | 169 격자는 **하드코딩 금지**. 서버 `parseRange` 1326 출력을 브라우저에서 집계 | grep 게이트 + 번들 검사 + "API 없이 정적만 서빙하면 격자가 안 그려진다" 는 실물 증명으로 고정 | P1 스펙 2절 |
| D15 | 차트 데이터는 **상용 서비스 스크래핑 금지**. `source` 컬럼 필수 | ToS 위반이고, 출처가 불투명하면 앱 자체를 신뢰할 수 없게 된다 | DESIGN 4.2 |
| D16 | 트레이너 기록은 **`data/trainer.db`** 로 차트 DB(`ggto.db`)와 **파일을 분리**한다 | `ggto.db` 는 `npm run seed`/`--replace` 로 언제든 재생성되는 **산출물**이고 기록은 되살릴 수 없는 **사용자 데이터**라 수명이 다르다. 한 파일에 두면 시드 재생성 사고 하나가 몇 달치 기록을 지운다. 기록은 차트를 `content_hash` 로만 참조하므로 파일 간 FK 가 필요 없다 | P3 스펙 1절 |
| D17 | 스팟 키 = **`pf:<content_hash>:<seq>:<combo>`**, 카테고리는 **상태 기계 파생** (손으로 붙이지 않는다) | 인포셋을 문자열로 식별하는 D9 의 연장이다. 차트를 `content_hash` 로 잡으면 재임포트로 `chart_set.id` 가 바뀌어도 기록이 살아남고, 콤보를 1326 키로 잡아야 블로커가 보존된다 (D4). 카테고리를 `preflopState` 에서 유도하면 6-max 차트가 들어올 때 `vs_3bet` 류가 규칙 추가 없이 생긴다. `ps:` 접두는 P6 포스트플랍용으로 예약 | P3 스펙 3.1·3.2 |
| D18 | 문서 다이어그램은 **SVG 이미지**로만. ASCII 아트 금지 | 박스 드로잉 문자는 폭이 환경마다 달라 깨지고, 색·강조·주석을 담을 수 없다. `docs/assets/*.svg` 에 두고 마크다운에서 참조한다 | P3M |
| D19 | 서버 바인드 기본값은 **`127.0.0.1`** 유지. LAN 노출은 `GGTO_HOST` 환경변수로 **명시적 opt-in** (`npm run start:lan`), 켜면 기동 로그에 경고 + LAN URL | 사용자가 휴대폰으로 쓰므로 같은 Wi-Fi 에서 닿아야 하는데, 이 서버에는 **인증이 없다**. 기본값을 열면 같은 네트워크의 누구나 트레이너 기록을 읽고 쓴다. 기본을 닫아 두고 위험을 아는 사람만 한 줄로 열게 한다. Tailscale 류 터널은 사용자 선택이며 스펙 밖 | P3M 7절 |
| D20 | 콤보 패널은 **접힘이 기본**이고 **격자 아래**에 펼쳐진다 (모바일·데스크톱 공통, 뷰어·트레이너 공통) | 우측 열에 두면 `w-96` 두 개가 격자 옆에 못 들어가 1280x720 에서 채점 박스와 "다음" 이 화면 밖(y=805)으로 밀렸다 (P3 R1 MINOR 1). 375px 에서는 격자와 채점 사이에 콤보 12줄이 끼어 verdict 를 못 봤다. "접힘 + 아래" 는 두 해상도의 원인을 한꺼번에 없앤다 | P3M 3절 / P3 R1 MINOR 1 |

## 기각된 것

- **직접 CFR 솔버 구현** — 검증된 AGPL 엔진 재구현. "쓸 만한 앱"까지 6개월+. 단 `Solver` 인터페이스 경계는 유지해 나중에 교체 가능
- **순수 TS 솔버** — Rust 대비 10~30배 느림
- **전부 Rust 원안** — P0~P3 연산은 1326 float 배열 조작이라 TS 로 충분
- **Python 백엔드** — 솔버가 Rust 라 PyO3 브릿지 + GIL. 레이어만 늘어남
- **Next.js** — SSR/SEO 불필요
